# ADR 0001: Структура ER-моделі бібліотеки відеоігор

## Status

Accepted

## Context

Для системи управління бібліотекою відеоігор потрібно визначити структуру сутностей та зв'язків між ними.

Важливо уникнути зайвого дублювання даних і зробити модель зрозумілою.

## Decision

Обрано модель із п'ятьма основними сутностями: User, Library, Game, Genre та Review.

Для зв'язків між Library і Game, а також Game і Genre використовується кардинальність багато-до-багатьох (M:N).

## Considered Options

**Варіант 1.** Використовувати зв'язки M:N без окремих асоціативних сутностей.

Переваги:
- Простіша концептуальна модель.
- Менше зайвих елементів на діаграмі.
- Відповідає вимогам завдання.

Недоліки:
- Не можна зберігати додаткові атрибути самого зв'язку.

**Варіант 2.** Створити окремі асоціативні сутності для кожного зв'язку M:N.

Переваги:
- Можливість додавати атрибути зв'язків.
- Більше можливостей для розширення моделі.

Недоліки:
- Ускладнення структури.
- Для поточної роботи такі сутності не потрібні.

## Decision Drivers

- Відповідність вимогам лабораторної роботи.
- Зрозуміла структура моделі.
- Відсутність зайвих сутностей.
- Можливість правильно відобразити кардинальності.

## Consequences

Модель залишається компактною та містить лише необхідні сутності. Зв'язки M:N не потребують окремих сутностей, оскільки в межах поточної предметної області вони не мають власних атрибутів.

Якщо в майбутньому виникне потреба зберігати додаткові дані про зв'язки, модель можна буде розширити.
